# 社区基准测试：RTX 4000 Ada 双 GPU 与三 GPU 层拆分对比

测量于 2026-10-02，在运行 Ubuntu 24.04.5 LTS 的 Dell PowerEdge R7515 上进行。这是社区对同一台主机上两种 Strata GPU 布局下相同 Qwen3.8-Flash-Next IQ3_S 模型的对比。

有用的结论很有限：在这台机器上，增加第三块功耗更低的 RTX 4000 SFF Ada 并未实质性提升解码吞吐量，而 16.6K token 的全新提示词场景则变得明显更慢。这与以下判断一致：当两块较快的显卡已经足以应对该工作负载时，额外的慢速流水线阶段所带来的负面影响超过了额外专家缓存容量带来的收益。

- 125.4 GiB 可用系统内存。

- GPU 0：NVIDIA RTX 4000 SFF Ada Generation，20,475 MiB，70 W 功耗限制。
- GPU 1：NVIDIA RTX 4000 Ada Generation，20,475 MiB，130 W 功耗限制。

- PCIe：两块 130 W 显卡均使用 x16 链路；其中一块在这些实验中协商为 **PCIe 3.0 x16**。确切的总线到链路映射未被保留，因此此处不对任何单卡作出 Gen4 声明。
- 存储类型：基准测试产物中**未保留**。
- Strata 引擎 0.1.35，本地为 Ada / SM89 构建，禁用视觉功能；除 SM89 目标外的确切编译器/构建标志未被保留。
- Strata 源码提交：`d9ab8435f654c368c586340d490915f6addf56a3`。

## 模型与配置

服务器报告的模型：`qwen3.8-flash-next-iq3_s`。

两次运行的通用设置：

- IQ3_S 模型包。
- 模型仓库/版本：原始基准测试产物中**未保留**。
- GGUF 系列：`Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S`；后续生产配置保留了两个分片名称 `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00001-of-00002.gguf` 和 `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00002-of-00002.gguf`。
- 原始 2026-10-02 运行的自定义包/配置来源及哈希：**未保留**。
- 131,072 token 上下文限制。
- INT8 KV。
- 视觉功能禁用。
- 单请求服务。
- 回环地址上的 OpenAI 兼容 `/v1/chat/completions` 端点。
- 本地冒烟测试套件中 temperature 0、top-p 1、seed 42。

GPU 布局：

1. **双 GPU：** GPU 1 + GPU 2，即两块 130 W 全高显卡。
2. **三 GPU：** GPU 1 + GPU 0 + GPU 2，在两块 130 W 显卡之间插入 70 W SFF 显卡。

Strata 自动选择层放置。对于双 GPU 运行，保存的启动日志报告 GPU 为 `[1, 2]`，自动层拆分，专家缓存为 8,092 个专家，使用 14.56 GiB 显存。确切的每 GPU 层边界未被保留。对应的详细三 GPU 启动日志在实验后被意外覆盖，因此此处不对确切的三 GPU 拆分边界或缓存数量作出声明。

## 工作负载

一个本地确定性的 12 请求冒烟测试套件在两种布局下原样重放。它包含小型数学、逻辑、Python、电子学、指令遵循、智能体规划、基础概率和长上下文提示词。最后一个用例是 16,591 token 的合成档案查找，包含两条相关记录和大量干扰项。

原始对比的原始请求提示词、响应、用量、墙钟时间、Strata 计时字段以及 MTP 草稿/接受计数器保存在：

- `results-2gpu.jsonl`
- `results-3gpu.jsonl`

对于后续的当前生产对照，每次运行的紧凑导出保存在：

- `results-2gpu-current.csv`
- `power-2gpu-current-summary.csv`
- `expert-cache-sweep-summary.csv`

紧凑的当前 CSV 记录了实际提示词/生成 token 数、复用 token 数、引擎提示词/解码吞吐量、客户端墙钟时间、结束原因以及 MTP 草稿/接受计数器。辅助扫描文件包含每个槽位数保留的聚合测量值；完整的每请求辅助追踪未被保留，因此报告不作其他声明。

此套件**不是标准化的模型质量基准测试**。有两个测试项有意或无意地不适合进行简单的自动准确性评分：

- `math_02_integer_system` 存储的预期答案是错误的（`1,8,15`）；方程实际由 `3,5,16` 满足，两次运行均推导出了该结果。
- `logic_02_implication` 按原文并非单一答案：B（`P is false`）和 C（`Q is true`）均可由前提推出。

若干响应在输出所请求的 `FINAL:` 行之前就达到了配置的输出 token 上限。因此自动通过计数仅作为测试框架诊断保留，不应被解释为模型准确性。

## 结果

| 配置 | 套件墙钟时间 | 解码中位数 tok/s | 解码均值 tok/s | 16.6K 提示词 tok/s | 16.6K 解码 tok/s | 16.6K 墙钟时间 |
|---|---:|---:|---:|---:|---:|---:|
| 2 x 130 W RTX 4000 Ada | 85.044 s | 72.95 | 71.83 | **2,110.3** | 72.9 | **9.843 s** |
| 2 x 130 W + 1 x 70 W RTX 4000 SFF Ada | 97.275 s | 73.70 | 72.08 | **778.6** | 75.0 | **23.146 s** |

对于此工作负载，增加第三块显卡仅使解码中位吞吐量变化约 **+1.0%**，而 16.6K 全新提示词吞吐量下降约 **63.1%**，长请求墙钟时间增加约 **135.2%**。套件总墙钟时间增加约 **14.4%**。

套件中的短请求部分几乎不变（双 GPU 上 75.201 s，三 GPU 上 74.129 s）。因此总体变慢主要由长提示词用例主导，而非自回归解码。

## 后续实验：将 SFF 用作辅助专家缓存设备

2026-10-03 的后续实验保留两块全高 RTX 4000 Ada 显卡作为层拆分对，仅将 RTX 4000 SFF Ada 用作实验性辅助专家缓存设备。

辅助缓存在 2,000 / 3,000 / 4,000 / 6,000 / 8,000 槽位下进行了扫描。这台机器上的最佳点约为 4,000 槽位。

此后续实验使用了当前生产风格配置，而非上述较轻量配置：

- 启用视觉功能；
- 262,144 token 最大上下文；
- INT8 KV；
- 32,768 常驻 KV 单元；
- 相同的 IQ3_S 模型系列。

由于这些差异，下面的后续数据不应与上述原始约 73 tok/s 的双 GPU 结果直接比较。相关的比较是在相同当前配置下，全新的纯双 GPU 对照与 SFF 辅助运行之间的对比。

### 已解析的当前生产启动配置

纯双 GPU 对照通过 Strata Docker 入口点启动，使用以下无凭据环境：

```text
FAMILY=qwen
MODEL=IQ3_S
CONTEXT=262144
VISION=yes
KV=int8
GPUS=1,2
LAYER_SPLIT=auto
```

在重新生成持久化设置状态后，解析出的引擎参数列表为：

```text
--pack /data/packs/iq3_s
--native /data/models/IQ3_S/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00001-of-00002.gguf
--ple-gguf /data/models/IQ3_S/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00002-of-00002.gguf
--expert-profile /opt/strata/data/expert-profile.bin
--expert-cache auto
--prefill auto
--spec 4
--spec-min-p 0.5
--mtp /data/mtp/rt
--max-context 262144
--kv int8
--kv-resident 32768
--vision
--vram-reserve-mib 700
```

确切的视觉编码器仓库/版本、包哈希、专家配置哈希、CPU 工作线程数以及存储设备在基准测试产物中**未保留**。保留的已解析参数列表中不存在显式的低内存、校准或实验性速度预测标志。

| 配置 | 短解码均值 | 短解码中位数 | 16.6K 预填充 | 长解码 | 长墙钟时间 |
|---|---:|---:|---:|---:|---:|
| 纯双 GPU，当前配置 | **68.52 tok/s** | **68.0 tok/s** | **2,117.5 tok/s** | **68.9 tok/s** | **10.064 s** |
| + SFF 辅助专家缓存，4,000 槽位 | **70.60 tok/s** | **71.9 tok/s** | **2,116.9 tok/s** | **70.1 tok/s** | **10.387 s** |

因此辅助设备确实执行了有用的工作：短解码平均提升约 3%，长解码提升约 1.7%。预填充实际上没有变化。相对于额外的设备和同步复杂性，收益很小。

GPU 侧功耗每 500 ms 采样一次。在最终的纯双 GPU 对照中，两块活跃的全高显卡在套件期间平均合计约 **141.5 W**。已安装的 SFF 显卡经核实处于空闲状态，**2 MiB 显存且 0% GPU 利用率**。在 4,000 槽位辅助运行中，三块显卡平均合计约 **164 W**。在此工作负载下，辅助设备以明显更差的 GPU 侧效率换取了几个百分点的解码吞吐量提升。

纯双 GPU 运行还显示了预期的工作负载分布：自回归解码通常使每块全高显卡远低于其 130 W 上限，而长上下文预填充则在两块显卡上产生接近满功耗的短时突发。

### 可复现性说明：持久化设置状态

在辅助扫描期间，一次名义上恢复的双 GPU 运行最初被发现仍在使用 SFF。`/data` 下的持久化 Strata 设置状态在容器重启后重新生成了先前存储的实验性参数：

```
--expert-cache-device1 3000 --split-device 2
```

尽管 Compose 环境已经恢复为 `GPUS=1,2` 和 `LAYER_SPLIT=auto`。

上述最终纯双 GPU 对照仅在重新生成设置并确认 SFF 已恢复为 **2 MiB 显存 / 0% GPU 利用率**后才被接受。在使用持久化 `/data` 卷复现拓扑 A/B 测试时，这一点值得检查。

## 方法与测量边界

本地回归测试框架的调用方式为：

```text
python3 baseline_v1.py
```

脚本本身未在此 PR 中保留。原始 2026-10-02 对比的提示词和生成设置嵌入在 JSONL 记录中，后续的当前生产对照按请求导出在 `results-2gpu-current.csv` 中。

对于当前纯双 GPU 对照：

- 保留了 12 请求套件的一次测量通过；并非每个提示词都有三次重复测量运行；
- 模型加载在基准测试前已完成，不计入请求墙钟时间；
- 每个保留的请求都报告 `reused_tokens = 0` / 引擎 `cache_n = 0`；
- 客户端墙钟时间涵盖完整的 HTTP 请求；
- 提示词/解码吞吐量来自 Strata 引擎计时字段，而非生成 token 数除以总墙钟时间；
- TTFT **未测量**；
- GPU 功耗/利用率/显存每 500 ms 使用 `nvidia-smi` 采样一次；
- 推理期间的 RAM 峰值和分页活动在保留的运行中**未测量**；
- 除已加载的模型/专家缓存之外的预热状态**未单独记录**。

这些限制是有意为之，而非用估算值填充。

## 主机内存带宽背景

该模型在主机内存中保留了一个大型专家区域，因此 DRAM 带宽可能与专家层性能相关。

在这些测量时，R7515 配备 **4 x 32 GB DDR4-3200 ECC RDIMM**，四个内存通道各一条 DIMM，平台为支持八个内存通道的 EPYC 7313P。

在此 4 通道配置上单独运行的 STREAM 测量结果：

| 线程数 | Copy | Scale | Add | Triad |
|---|---:|---:|---:|---:|
| 8 | **80.78 GB/s** | **55.15 GB/s** | **59.26 GB/s** | **60.13 GB/s** |
| 16 | **79.66 GB/s** | — | — | — |

Copy 从 8 线程到 16 线程没有提升，表明当前配置已经接近其可用内存带宽上限，而非受限于核心数。

计划中的后续实验将填充剩余四个通道（总计 8 x 32 GB），并重复 STREAM 和相同的纯双 GPU Strata 基准测试。该测试应有助于将 GPU 侧缓存效应与主机专家层带宽效应区分开来。

## 解读

这一单主机结果支持一个有限的工程结论：当额外的 GPU 明显慢于现有阶段时，它并不自动对层拆分推理有益。在这台 R7515 上，额外的 20 GB SFF Ada 显存在原始三阶段层拆分中并未产生可测量的解码优势，而长提示词预填充在加入第三阶段后则慢得多。

辅助专家缓存后续实验增加了一个更细致的结果。当 SFF 被排除在层流水线之外时，它可能有用：约 4,000 槽位的辅助设备将解码提升了几百分点。然而，在这个特定系统上，该收益不足以证明额外的 GPU 侧功耗和拓扑复杂性是合理的。

这不应被推广到所有三 GPU 系统。当两块较快的显卡无法容纳足够的路由专家工作集时，当各显卡的每层性能更接近时，或者当主机内存带宽成为主要瓶颈时，第三块显卡仍可能有帮助。

## 局限性

- 一台主机、一个模型、一种量化、一个 Strata 引擎系列，以及一个小型合成工作负载。
- 原始层拆分基准测试和后续专家缓存扫描使用了不同的生产设置；比较仅在每个受控对内部进行。
- STREAM 与推理运行分开测量，而非同时进行。
- 自动选择的每 GPU 确切层边界未被保留；详细的三 GPU 启动日志在实验后被意外覆盖。
- 运行是单次执行，而非在每个提示词长度上重复取中位数。
- GPU 时钟未固定。
- 冒烟测试套件是为本地回归检查设计的，而非标准化准确性测量。
- 不声称观察到的变慢仅由 GPU 功耗限制引起；层分配、时钟、PCIe 行为、缓存驻留、主机内存带宽和流水线调度都可能有所贡献。
