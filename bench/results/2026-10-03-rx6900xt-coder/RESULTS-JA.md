# Strata Coder 实机基准测试

2026年10月3日，在本机安装了 Strata **v0.1.38** 的 **Coder IQ1_M**，并使用 Radeon RX 6900 XT 进行了测量。将 CPU 工作线程数设置为 31 时，回答生成在各条件下的中位数约为 **45〜48 token/秒**。

本页面记录了在正式发布版本上进行的首次测量。在随后的[CPU 线程组支持与重新测量](../2026-10-03-windows-groups/README.md)中，63 工作线程的生成速度得到了改善。目前以修正版的自动选择 63 工作线程启动，不建议将标准设置更改为 31 工作线程。

## 本机与测量条件

- GPU：Radeon RX 6900 XT，16GB VRAM
- CPU：Threadripper 3990X，64 核／128 线程
- 内存：128GB，DDR4-3200
- OS：Windows 11 Pro，AMD 驱动 32.0.21045.5002
- Strata：v0.1.38，官方 Windows HIP 版
- 模型：Qwen3.8-Flash-Next Coder IQ1_M
- 上下文容量 65,536，无思考模式，无图像，temperature 0，输出 256 token
- 各条件 3 次。排除启动和预热，在输入缓存复用为 0 的情况下测量。日常桌面应用保持启动状态。

## 速度

下表为 3 次的中位数。「生成速度」是除去输入处理时间后，写出回答的速度。

| 输入长度 | 标准设置：63 工作线程 | 采用设置：31 工作线程 | 采用设置的输入读取 | 首字符延迟 |
| --- | ---: | ---: | ---: | ---: |
| 短代码生成（94 token） | 12.5 token/秒 | **48.0 token/秒** | 46.8 token/秒 | 2.04 秒 |
| 约 4 千（实际 4,022） | 11.6 token/秒 | **45.3 token/秒** | 312.5 token/秒 | 12.93 秒 |
| 约 3 万 2 千（实际 32,685） | 6.1 token/秒 | **46.0 token/秒** | 352.1 token/秒 | 93.02 秒 |

31 工作线程设置下的生成速度范围为：短输入 44.9〜49.5，约 4 千 43.6〜45.4，约 3 万 2 千 41.5〜46.8 token/秒。

还比较了 15 工作线程，短输入的中位数为 44.4 token/秒。在尝试的 63、31、15 工作线程中，31 工作线程最快，相比标准设置，短输入的生成速度约为 3.8 倍。GPU 缓存容量会因自动调整而略有波动，因此并非断定速度慢的原因是 CPU 的特定缺陷。

读取长文的时间在首次是必要的。在继续该对话的追加测试 1 次中，32,962 token 中有 32,940 token 被复用，**首字符延迟 0.67 秒，生成 47.3 token/秒**。每次从头读取长文与继续对话的等待时间不同。

## 使用方法

当前聊天界面：**http://127.0.0.1:8081/**

OpenAI 兼容 API：**http://127.0.0.1:8081/v1**（仅限本机内，API 密钥任意，模型名任意）。

下次启动请打开 `C:\Dev\Strata\run-coder-iq1_m.bat`。当前设置为 CPU 线程组支持版・工作线程数自动选择（本机为 63）。上表中的 31 为首次测量时的设置。如果同一服务器正在运行，可直接使用上述聊天界面。

应用本体：`C:\Dev\Strata`。模型数据：`C:\Dev\Strata-data`。GGUF 本体合计 58.41GB，另需辅助模型、转换数据、运行环境的容量。

## 验证与记录

模型本体 2 个文件的 SHA-256・大小与发布方的固定版本一致。GPU 自检、21 次正式测量、对话继续测试均成功。另外生成的小型 Python 函数也通过了 2,001 输入的验证。这并不保证一般的代码质量。

标准设置推理中的内存记录显示，引擎使用的 RAM 约为 25.5GiB，整机使用的 RAM 约为 71.9GiB，整个桌面的使用 VRAM 约为 15.6GiB。这是瞬时值，并非最大值。
