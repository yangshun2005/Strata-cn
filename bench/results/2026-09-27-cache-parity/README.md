# 2026-09-27：专家缓存开启与关闭对比（Issue #23）

问题：引擎过去会在启动时警告“GPU 命中路径不正确……其产生的任何输出也不正确”。专家缓存会让输出变差吗？

方法：教师强制（teacher-forced）。`strata --dump-logits` 逐 token 运行文本，并在每个位置写出 logits，因此两次运行看到相同的文本，每个位置的下一个 token 预测都可以比较：
- 缓存关闭：不使用 `--expert-cache`，每个路由专家由 CPU 池计算；
- 缓存开启：`--expert-profile pack/profile-decode-8k.bin --expert-cache auto`，使用最多的 5,130 个专家放在 GPU 上。

Q2_0，RTX 5070，三个冻结提示词的前 512 或 1,024 个 token。

| 文本 | 相同 top-1 | KL 中位数 | 困惑度（关闭） | 困惑度（开启） | 开启 - 关闭（nats/token） |
|---|---:|---:|---:|---:|---:|
| 代码智能体（512） | 97.7% | 3.0e-04 | 2.672 | 2.630 | -0.016 +- 0.019 |
| 长文档（1,024） | 96.2% | 4.5e-03 | 29.844 | 29.843 | -0.000 +- 0.005 |
| 聊天（1,024） | 95.0% | 4.4e-03 | 18.380 | 18.301 | -0.004 +- 0.006 |
| **全部 2,557 个 token** | | | | | **-0.005 +- 0.005** |

解读：
- 缓存在 2-5% 的位置上改变了两个几乎相等的候选者中哪一个胜出。大多数翻转的 top-2 差距小于 0.5 logits（`logits-compare.txt`）。
- 两侧都不更准确：实际文本的困惑度相同，在 1 个标准误以内。
- GPU 专家和 CPU 以不同的浮点运算顺序计算相同的量化专家。两者都是对模型的同等良好的近似。

启动警告源自第 328 轮，当时 GPU 命中路径存在真实故障（从 token 0 开始出现偏差）。该故障早已修复，并由 `expert_parity`、`native_expert_parity` 以及分组内核的测试覆盖。自引擎 0.1.8 起，该警告已被一行准确的提示所取代。
