# GPU 间的层拆分（2026-09-29）

**测试机（一位社区成员的 PC，代号 "RIBPC"）：**
- Ryzen 9 9950X3D，62 GB DDR5，Windows 11，CUDA 13.1。
- RTX 5080 16 GB（x16），RTX 3090 24 GB（x4 gen4，约 6 GB/s），RTX 2080 Ti 22 GB（x4 gen3，Turing sm_75；实验性的 `STRATA_EXPERIMENTAL_SM75` 构建）。

**模型：** Coder（GSQ-RCO IQ1_M，48 层 x 256 专家 = 12,288 个专家对，约 23 GB 专家权重），32K 上下文，int8 KV，`--prefill auto`，`--spec 4`。它是唯一能装进这台机器内存和磁盘的模型。

**工具：** `rib_pp.py`（在 2.7K/8K/16K/28K token 处放置针提示，代码词位于 50% 深度处；一个必须复用其检查点的两轮对话；对一段故事和一个代码提示进行贪婪解码）以及 `rib_norepeat.py`（Phase A 的 no-repeat 和健全性用例）。原始结果位于 `data/`。

## 速度

**Prompt tok/s** 在 16K / 28K token 处，以及 **decode tok/s** 针对故事 / 代码（贪婪；K 扫描中取三次重复的平均值）：

| 配置 | 拆分 | Prompt 16K | Prompt 28K | Decode 故事 | Decode 代码 | Decode 命中率 |
|---|---|---|---|---|---|---|
| 0.1.20，仅 5080 | - | 2,045 | 2,005 | 83.2 | 88.2 | 70-84% |
| 本分支，仅 5080 | - | 2,017 | 1,974 | 83.1 | 88.0 | 70-84% |
| 本分支，仅 5080，3 次重复（自适应交换学习 prompt） | - | 1,726 | 1,970 | 86.7 | 105.2 | 91-92% |
| 仅 3090 | - | 1,253 | 1,211 | 71.7 | 92.9 | 86-93% |
| 5080 + 3090 | K=18 | 1,547 | 1,694 | 77.2 | 103.8 | 99.9% |
| 5080 + 3090 | K=22 | 1,840 | 2,074 | 80.2 | 106.4 | 99.8% |
| 5080 + 3090 | K=24 | 1,978 | 2,258 | 83.5 | 109.5 | 99.5% |
| **5080 + 3090** | **K=26** | **2,039** | **2,357** | **83.8** | **109.7** | 99.3% |
| 5080 + 3090 | K=28 | 2,011 | 2,287 | 83.5 | 112.5 | 99.0% |
| 5080 + 3090 | K=30 | 1,935 | 2,218 | 81.1 | 109.6 | 98% |
| 5080 + 3090 | K=32 | 1,818 | 2,063 | 83.0 | 108.7 | 98% |
| 5080 + 3090 | auto（K=22） | 2,037 | 2,073 | 79.5 | 108.9 | 99.7% |
| 3090 + 5080 | auto（K=30） | 1,672 | 1,876 | 90.3 | 105.1 | 99.4% |
| 5080 + 2080 Ti + 3090 | auto（22, 23） | 1,687 | 1,847 | 67.6 | 89.6 | 99.7% |
| 5080 + 3090 + 2080 Ti | 首次 auto（12, 33） | 1,148 | 1,144 | 51.9 | 69.7 | 100% |
| 5080 + 2080 Ti | 首次 auto | 914 | 906 | 45.5 | 58.0 | 97% |

决定因素：

- **对 Coder 而言最佳的双 GPU 拆分是 K=26-28。** 在 16-28K 时 prompt 比仅用 5080 快 +18-20%；decode 在故事上持平，在代码上快 +4-7%。
- **驻留很快饱和：每层 GPU 速度起决定作用。** 从 K=18 起，两个缓存都持有 98-100% 的路由专家。把层移到更快的卡上才有帮助：3090 每层每窗口耗时 0.50 ms，5080 为 0.33 ms（`STRATA_SPLIT_TIMING`，即每个阶段的 "wait for the GPU"）。
- **Decode 受该 GPU 时间限制。** 一块 5080 在其缓存自适应后，每窗口花 16.3 ms 等待其 GPU，5.5 ms 在 CPU 池中。拆分消除了池（0.8-1.0 ms），但增加了较慢卡的层：K=24 时为 7.9 + 12.1 ms。每层 GPU 的一半（内核加上发布每层专家计划的主机往返）是下一个要削减的目标，对单 GPU 也是如此（perf-review-plan E-6）。
- **第三块较慢的卡代价大于其承载量。** 2080 Ti 的单层阶段每窗口耗时 3.1 ms。对于一个已经能装进两块卡的模型，把它排除在外。只有当两块较快的卡无法容纳大部分路由专家时（更大的模型；在这台机器 62 GB 内存上无法测试）它才划算。
- **Prompt 分块：** 用 1024 而非 2048 每卡释放约 0.7 GB，但 prompt 读取慢 7-12%。

## 自动放置

`--layer-split auto` 为每种放置（最多三块 GPU 的每种放置）预测一个 decode 窗口的时间，并保留最快的：

- **每层时间**来自 SM 数 x 时钟（RTX 5080 为 0.33 ms）；
- **缓存内容：** 每张卡各层的已剖析专家对，最热的在前，与填充时一致；
- **rank r 的路由质量**取为 (r+1)^-1.2（与扫描的命中率吻合在 0.1-1% 以内）；
- **未命中质量**每单位代价 190 ms（拟合到扫描的最佳 K；`STRATA_SPLIT_MISS_MS` 可覆盖）。

它在 5080 + 3090 上选择了 K=22：在 prompt 上与最佳固定拆分相差 0-12%，在 decode 上持平。它给较慢的第三块卡分配单层。
