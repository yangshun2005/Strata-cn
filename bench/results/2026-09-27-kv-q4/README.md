# 2026-09-27：带 Hadamard 旋转的 Q4_0 KV（PR #21，`--kv q4_0`）

PR #21（code-martin）新增了一种 4 位 K/V 格式：先对 K、V 和 Q 做正交归一化的 256 点 Walsh-Hadamard 旋转，然后
使用 ggml 的 `q4_0` 块（每个 cell 和层 576 B，而 int8 为 1,056 B）。

## 合并时所做的集成修复

- **Q4 + KV 流式（`--kv-resident`）。** 该 PR 没有为 Q4 提供主机副本，并跳过了暂存，因此在开启流式时，
  prompt 路径通过驻留映射的 -1 条目写入 K/V（越界写入）。
  - Q4 现在是 `kv_stream` 中的第三种格式：主机副本、块驻留、prompt 路径暂存、MTP ring 和 STATE_HASH。
  - `kv_stream_parity` 以逐位方式检查它，流式与驻留对比，并带 ring 恢复。
- **重复注意力。** 逐 token 解码路径运行了两次注意力，第一次是在选择结果的块被设为驻留之前；现在只运行一次。
- **平局决胜。** 组最大值的平局决胜现在在各 lane 之间是确定性的：|x| 相等且符号相反时，
  可能给一个块两个 scale。
- **丢弃了无关改动：** 重复路径修复（已在 0.1.7 中）、个人 `.gitignore` 条目，以及重新编码的 CMakeLists。

`kv_q4_parity`（该 PR 的测试）和全部 70 个 ctest 测试均通过。

## 质量（teacher-forced，`tools/kv_precision_compare.py`）

相同文本、相同固定专家集（Q2_0，3,000 个槽位，`--adapt-swaps 0`）；只有 `--kv` 不同。fp16 为参考。

| 文本 | KV | 与 fp16 相同的 top-1 | 平均 KL | 困惑度 | 相对 fp16（nats/token） |
|---|---|---:|---:|---:|---:|
| code agent（512） | int8 | 98.4% | 0.014 | 2.649 | -0.011 +- 0.006 |
| | q4_0 | 95.7% | 0.030 | 2.598 | -0.031 +- 0.014 |
| document（1,024） | int8 | 95.6% | 0.009 | 30.18 | +0.012 +- 0.005 |
| | q4_0 | 91.3% | 0.039 | 32.26 | **+0.078 +- 0.011** |
| chat（1,024） | int8 | 95.5% | 0.009 | 18.24 | -0.003 +- 0.005 |
| | q4_0 | 90.7% | 0.028 | 18.52 | +0.012 +- 0.008 |
| document，8K（每第 8 个位置） | int8 | 92.3% | 0.114 | 7.63 | -0.013 +- 0.020 |
| | q4_0 | 88.0% | 0.297 | 8.65 | **+0.112 +- 0.037** |

- **int8 与 fp16 无法区分**（各处都在约 2 个标准误以内）。
- **q4_0 带来可测量的精度损失，且随上下文增长而增大：**
  - document 困惑度在 1K 时 +8%，在 8K 时 +12%；
  - 相对 fp16 的 KL 是 int8 的 2.6-4.2 倍；
  - code 和 chat 接近中性。
- **使用 `--kv q4_0 --kv-resident 32768` 的 needles：5/5**（1K、32K、128K 在 10% 和 90% 深度，262K；
  `needles-q4.*`）。检索能力保持。

## 速度与内存（Q2_0，128K，matrix bench，`--kv-resident 32768`）

| KV | 专家槽位 | 解码 tok/s | Tokens/round | Rounds/s | RAM 中的 K/V |
|---|---:|---:|---:|---:|---:|
| int8（`kv-stream/matrix-stream`） | 4,044 | 62.4 | 2.52 | 24.8 | 1.52 GiB |
| q4_0（`matrix-q4`） | 4,190 | 67.4 | 2.62 | 25.7（+3.7%） | 0.83 GiB |

在不使用流式的情况下（上下文最多 64K，或 RAM 不足以支持流式），q4_0 则会将 VRAM 中的整个 KV 缓存减半。

## 决策

`--kv q4_0` 是一个用户选项：
- `START-HERE.bat --kv q4_0`，或问题设置中在上下文超过 8K 时询问；
- 或在 `strata-*.json` 中设置 `--kv q4_0`。

int8 仍为默认值：所有已发布的质量数据都是用 int8 测量的，而 q4_0 的精度损失是真实存在的，
尽管它通过了 needles。
