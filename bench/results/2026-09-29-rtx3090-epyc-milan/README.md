# RTX 3090 / EPYC 7453 原生初步结果

Issue：[#165](https://github.com/Niko1221/Strata/issues/165)
引擎：Strata v0.1.26，源码构建于 `ac8b251`
状态：初步结果；已向上游请求提示词集与测试框架指导。

## 硬件

| 组件 | 客户机可见详情 |
|---|---|
| CPU | AMD EPYC 7453，20 vCPU，AVX2；未暴露 AVX-512 |
| 内存 | Ubuntu 24.04.5 KVM 客户机可见 165 GiB；物理 DIMM 布局与带宽未验证 |
| GPU | 2x RTX 3090 24 GB；每卡报告最高 PCIe Gen4 x16；驱动 595.91.07 |
| 功耗限制 | 每块 GPU 配置为 280 W；默认值为 350 W / 420 W，最大可调限制为 366 W / 450 W |
| 存储 | 541 GiB ext4 客户机数据盘；宿主机存储布局未验证 |

上述功耗值为配置的上限，而非实测工作负载功耗。硬件信息采集期间的闲置功耗约为 35 W / 29 W。

## 方法

原生 Linux 环境，基于 v0.1.26 本地构建，`--prefill auto`，使用随附的专家配置，自动专家缓存，int8 KV，MTP 开启，图像关闭，实验性速度预测关闭。每块 GPU 的功耗限制为 280 W。原生运行使用 systemd 服务并设置 `LimitMEMLOCK=infinity`；其他 llama-swap 模型容器已停止。

本地 API 测试框架使用公开的 Strata 源码树作为提示词语料，配合生成的任务，`temperature: 0`，`reasoning_effort: none`，`max_tokens: 256`。它并非上游的代码智能体提示词集或测试框架。运行使用唯一请求 ID，速度模式下不重用对话。每个速度单元格运行三次，取中位数汇总；记录实际的 `usage.prompt_tokens`，因为标称上下文标签可能存在偏差。首次解码运行也一并展示。部分请求因 EOS 提前结束，因此实际生成数量见原始 JSON。

尚未进行校准对比、上游提示词对比、`STRATA_SPLIT_TIMING` 阶段计时或负载下功耗采集。在获得所请求的上游方法之前，所有与上游的提示词/解码对比仅供参考。

## 结果

汇总表见 [`matrix.md`](matrix.md)，所有成功运行记录见 [`matrix.json`](matrix.json)。每次运行的源 JSON、日志、本地测试框架以及脱敏的硬件信息位于 [`data/`](data/)。

要点：

- 单块 3090 上的 IQ3_XXS：1K–262K 单元格，各运行三次；262K 提示词分别为 232,183 / 259,589 / 261,068 tokens，均在 262,144 上下文范围内。
- 32K 下的 Coder IQ1_M：单 GPU 中位解码 66.8 tok/s；双 GPU 自动（K=19）中位数 98.6 tok/s。
- 固定 Coder K 扫描：K=22 是观测到的最高三次运行中位数（103.3 tok/s）；由于提示词独立生成，这并非配对排名。
- IQ3_XXS 与 IQ3_S 双 GPU 自动在 32K 下均选择 K=24。
- IQ3_XXS 与 IQ3_S 针测在测试的单/双配置下于 8K / 16K / 28K 均通过 3/3；两者的两轮检查点重用均通过。

## 限制与后续工作

- 上游提示词/测试框架尚不可用；当前所有速度数据均使用本地源码树语料。
- 客户机暴露一个 NUMA 节点和 165 GiB 内存，但物理 DIMM 拓扑与内存带宽未知。
- PCIe x16 是报告的最大链路宽度；引擎探测约为 23–26 GB/s。在声称直接的 x16 与 x4 对比之前，需在持续负载下验证 PCIe 代际/宽度。
- Coder 双 GPU 针测/两轮检查以及双 GPU 计时细分尚未运行。
- K=18 有一次成功运行，为 83.1 tok/s；一次重复启动在上传稠密权重时因内存不足错误失败，因此它不是三次运行的中位数。
- 校准/默认值对比以及 IQ3_S 单 GPU 结果仍待完成。
